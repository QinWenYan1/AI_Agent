## ✅ 知识点1: 什么是智能体——定义与四要素

**任何能通过传感器感知环境、并自主地通过执行器采取行动以达成目标的实体**

- 在探索任何一个复杂概念时，最好从一个简洁的定义开始。"智能体"并不是 LLM 时代的新发明——它是人工智能领域数十年的核心概念，理解它的定义是后续一切讨论的地基。

- **智能体（Agent）的定义**：任何能够通过 `传感器（Sensors）` 感知其所处 `环境（Environment）`，并**自主**地通过 `执行器（Actuators）` 采取 `行动（Action）` 以达成特定目标的实体

- **四个基本要素：**

  - **环境**：智能体所处的外部世界。自动驾驶汽车的环境是动态变化的道路交通；交易算法的环境是瞬息万变的金融市场
  - **传感器**：持续感知环境状态。摄像头、麦克风、雷达，或各类 `应用程序编程接口（Application Programming Interface, API）` 返回的数据流，都是感知能力的延伸
  - **执行器**：对环境施加影响。可以是物理设备（机械臂、方向盘），也可以是虚拟工具（执行一段代码、调用一个服务）
  - **`自主性（Autonomy）`**：真正赋予智能体"智能"的要素。智能体并非只是被动响应外部刺激或严格执行预设指令的程序，它能够基于其**感知和内部状态进行独立决策**，以达成设计目标

- 这种从感知到行动的闭环，构成了所有智能体行为的基础。

> ⚠️ **关键区分**：普通程序是"被动执行预设指令"，智能体是"基于感知和内部状态独立决策"——差异就在**自主性**上

## ✅ 知识点2: 传统视角下的智能体——五种类型的演进

**从被动反应到主动学习：一条"问题驱动"的演进路线**

在 `大语言模型（Large Language Model, LLM）` 热潮出现之前，AI 先驱们已对"智能体"探索了数十年。这些"传统智能体"并非单一的静态概念，而是从简单到复杂、从被动反应到主动学习的清晰演进路线——每一代新类型都在回答上一代回答不了的问题。

- **`反射智能体（Simple Reflex Agent）`**
  - 决策核心：工程师明确设计的"条件-动作"规则（对应原作图 1.2 决策逻辑示意图）
  - 经典例子：自动恒温器——若室温高于设定值，则启动制冷
  - 特点：完全依赖当前感知输入，**不具备记忆或预测能力**，像一种"数字化的本能"，可靠高效
  - 局限：无法应对需要理解上下文的复杂任务
- **`基于模型的反射智能体（Model-Based Reflex Agent）`**
  - 回答的问题：*"世界现在是什么样子的？"*——当当前感知不足以作为决策的全部依据时
  - 核心：拥有内部的 `世界模型（World Model）`，追踪环境中无法被直接感知的方面
  - 例子：隧道中行驶的自动驾驶汽车——摄像头暂时看不到前车时，内部模型仍维持对那辆车存在、速度和位置的判断
  - 意义：拥有初级的"记忆"，决策基于更连贯、更完整的世界状态
- **`基于目标的智能体（Goal-Based Agent）`**
  - 回答的问题：*"我应该做什么才能达成目标？"*
  - 核心：不再被动反应，而是**主动地、有预见性地**选择能导向某个特定未来状态的行动
  - 例子：GPS 导航系统——目标是到达公司，基于地图数据（世界模型），通过搜索算法（如 `A*算法`）`规划（Planning）`出最优路径
  - 核心能力：对未来的考量与规划
- **`基于效用的智能体（Utility-Based Agent）`**
  - 回答的问题：*"哪种行为能为我带来最满意的结果？"*——当多个目标相互冲突时
  - 核心：为每个可能的世界状态赋予一个**效用值**（满意度高低），目标是**最大化期望效用**
  - 例子：不仅希望到达公司，还希望时间最短、最省油、避开拥堵——在冲突目标间权衡
  - 意义：决策更接近人类的理性选择
- **`学习型智能体（Learning Agent）`**
  - 回答的问题：如果智能体能不依赖人类设计师的先验知识，而是**与环境互动自主学习**呢？
  - 核心：`强化学习（Reinforcement Learning, RL）` 是最具代表性的实现路径
  - 结构：一个**性能元件**（即前面讨论的各类智能体）+ 一个**学习元件**——学习元件观察性能元件行动带来的结果，不断修正其决策策略
  - 例子：学下棋的 AI 从随机落子开始，赢棋获得正向奖励，经大量自我对弈发现致胜棋路；`AlphaGo Zero` 是里程碑——通过强化学习发现了超越人类既有知识的策略

**演进脉络总结**：从简单的恒温器，到拥有内部模型的汽车，再到能规划路线的导航、懂得权衡利弊的决策者，最终到可通过经验自我进化的学习者——这条路线为理解更前沿的智能体范式打下了必要基础。

> ⚠️ **关键区分**：五种类型的分水岭是**各自回答的核心问题不同**——"现在该做什么"→"世界是什么样"→"如何达成目标"→"怎样最满意"→"如何自己变得更好"
>
> 💡 **理解技巧**：这是一条"问题驱动"的演进链：每一代新类型的出现，都是因为上一代暴露了它解决不了的局限
>
> 📋 **术语提醒**：第一个类型在原作 1.1.1 正文中写作"**反射智能体（Simple Reflex Agent）**"（图 1.2 标题称"简单反射智能体"）；注意与知识点4中分类维度二的"反应式智能体"措辞区分

## ✅ 知识点3: 大语言模型驱动的新范式

**核心不再是编写代码，而是引导一个通用的"大脑"去规划、行动和学习**

以 `GPT（Generative Pre-trained Transformer）` 为代表的大语言模型，正在显著改变智能体的构建方法与能力边界。LLM 智能体的核心决策机制与传统智能体存在本质区别。

**表 1.1 传统智能体与 LLM 驱动智能体的核心对比**（📋 原作此表以图片呈现，此处按正文描述整理）：

| 对比维度 | 传统智能体 | LLM 驱动智能体 |
|---------|-----------|---------------|
| 核心引擎 | 工程师编写的规则、模型、效用函数 | 大语言模型的通用推理能力 |
| 知识来源 | 显式编程与先验知识构建 | 海量数据预训练获得的**隐式世界模型** |
| 交互方式 | 结构化输入、确定且有边界的行为 | 直接处理高层级、模糊、充满上下文的自然语言指令 |
| 能力特性 | 专用、行为可预期 | 灵活、通用、具备**涌现能力** |

**"智能旅行助手"示例**：当接收到"规划一次厦门之旅"这样的模糊指令时，LLM 智能体展现出三点新能力（在此之前，用户需要在天气、地图、预订网站等专用应用间手动切换，自己扮演信息整合与决策的角色）：

- **规划与推理**：将高层级目标分解为一系列逻辑子任务：`[确认出行偏好] -> [查询目的地信息] -> [制定行程草案] -> [预订票务住宿]`——这是一个内在的、由模型驱动的规划过程
- **工具使用**：识别到信息缺口时主动调用外部工具补全。例如调用天气查询接口获取实时天气，并基于"预报有雨"这一信息，在后续规划中倾向于推荐室内活动
- **动态修正**：将用户反馈（如"这家酒店超出预算"）视为新的约束，据此调整后续行动、重新搜索推荐。整个"**查天气 → 调行程 → 订酒店**"流程展现了根据上下文动态修正自身行为的能力

**核心趋势**：我们正从开发专用自动化工具，转向构建能自主解决问题的系统。核心不再是编写代码，而是引导一个通用的"大脑"去规划、行动和学习。

> ⚠️ **关键区分**：传统智能体的能力上限 = 工程师显式编码的知识量；LLM 智能体的能力来自预训练获得的隐式世界模型与涌现能力
>
> 💡 **理解技巧**：三点新能力正好对应后面的实践章——规划与推理（Thought）、工具使用（Action）、动态修正（Observation 反馈进下一轮）

## ✅ 知识点4: 智能体的类型——三个分类维度

**同一个智能体，可以从三个互补的维度被分类**

回顾智能体的演进后，原作从三个互补维度对智能体进行分类——它们回答的是三个不同的问题：内部怎么决策？决策花多长时间？知识以什么形式存在？

**（1）基于内部决策架构的分类**

- 由《Artificial Intelligence: A Modern Approach》（AIMA）系统性提出
- 即 1.1.1 节的经典分类阶梯：从简单的**反应式**智能体 → 引入内部模型的**模型式**智能体 → 更具前瞻性的**基于目标**和**基于效用**的智能体
- **学习能力**是一种可赋予上述所有类型的**元能力**，使其能通过经验自我改进

**（2）基于时间与反应性的分类**

这个维度揭示了智能体设计的核心权衡：追求速度的 `反应性（Reactivity）` 与追求最优解的 `规划性（Deliberation）` 之间的平衡（对应原作图 1.3 决策时间与质量关系图）。

- **`反应式智能体 (Reactive Agents)`**
  - 特点：对环境刺激近乎即时响应，决策延迟极低；遵循从感知到行动的直接映射，不做或只做极少未来规划
  - 归属：简单反射和基于模型的智能体属于此类
  - 优势：**速度快、计算开销低**——动态环境中至关重要
  - 例子：安全气囊系统必须在碰撞发生的毫秒内反应；高频交易机器人靠反应式决策捕捉稍纵即逝的机会
  - 代价：缺乏长远规划的"短视"，容易陷入局部最优，难以完成需要多步骤协调的复杂任务
- **`规划式智能体 (Deliberative Agents)`**
  - 特点：行动前先利用内部世界模型，系统地探索未来的各种可能性，评估不同行动序列的后果，寻找达成目标的最佳路径
  - 归属：基于目标和基于效用的智能体是典型的规划式智能体
  - 类比：棋手不只看眼前一步，而是预想对手应对，规划后续几步甚至十几步棋路
  - 优势：决策的战略性和远见，能处理商业计划、长途旅行规划等复杂任务
  - 代价：高昂的时间和计算成本——瞬息万变的环境中，最佳行动时机可能在深思熟虑中错过
- **`混合式智能体 (Hybrid Agents)`**
  - 动机：现实任务往往既需要即时反应，也需要长远规划（旅行助手既要对"这家酒店太贵了"即时调整，又要规划数天的完整方案）
  - 经典分层架构：底层是快速反应模块处理紧急情况，高层是审慎规划模块制定长远目标
  - **现代 LLM 智能体的混合模式**：在"思考-行动-观察"循环中把两种模式融为一体——
    - `规划（Reasoning）`：在"思考"阶段，LLM 分析当前状况、规划下一步行动——这是**审议过程**
    - `反应（Acting & Observing）`：在"行动"和"观察"阶段，与外部工具或环境交互并立即获得反馈——这是**反应过程**
  - 效果：把需要长远规划的宏大任务，分解为一系列"规划-反应"的微循环

**（3）基于知识表示的分类**

这是最根本的维度：智能体用以决策的知识，以何种形式存于其"思想"之中？这是 AI 领域持续半个多世纪的辩论核心。

- **`符号主义 AI（Symbolic AI）`**
  - 核心信念：智能源于对**符号的逻辑操作**——符号是人类可读的实体（词语、概念），操作遵循严格的逻辑规则
  - 类比：一丝不苟的图书管理员，将世界知识整理为清晰的规则库和知识图谱
  - 优势：**透明和可解释**——推理步骤明确、决策过程可完整追溯，在金融、医疗等高风险领域至关重要
  - "阿喀琉斯之踵"：**脆弱性**——依赖完备的规则体系，充满模糊和例外的现实世界中，任何未覆盖的新情况都可能导致系统失灵，即"知识获取瓶颈"
- **`亚符号主义 AI（Sub-symbolic AI）`**
  - 又称连接主义：知识并非显式规则，而是**内隐地分布**在大量神经元组成的网络中，是从海量数据中学到的统计模式；神经网络和深度学习是其代表
  - 类比：牙牙学语的孩童——不学"猫有四条腿、毛茸茸、会喵喵叫"的规则，而是看过成千上万张猫的图片后，神经网络能辨识"猫"的视觉模式
  - 优势：**模式识别能力**和对噪声数据的**鲁棒性**；轻松处理图像、声音等非结构化数据
  - 缺陷：被视为 `黑箱（Black Box）`——识别准确却无法合理解释"为什么"；在纯逻辑推理任务上表现不佳，有时会产生看似合理却事实错误的**幻觉**
- **`神经符号主义 AI（Neuro-Symbolic AI）`**
  - 目标：融合两大范式的优点——既能像神经网络一样从数据中学习，又能像符号系统一样进行逻辑推理；弥合感知与认知、直觉与理性的鸿沟
  - 卡尼曼（Daniel Kahneman）《思考，快与慢》（Thinking, Fast and Slow）的双系统理论是绝佳类比（对应原作图 1.4）：
    - **系统 1**：快速、凭直觉、并行的思维模式 ≈ 亚符号主义的模式识别能力
    - **系统 2**：缓慢、有条理、基于逻辑的审慎思维 ≈ 符号主义的推理过程
  - **LLM 智能体是神经符号主义的极佳实践**：内核是巨大的神经网络（模式识别与语言生成），但工作时会生成一系列结构化的中间步骤——思想、计划、API 调用——这些都是明确的、可操作的符号，实现了感知与认知、直觉与理性的初步融合

> ⚠️ **关键区分**：反应式 vs 规划式不是"谁更好"，而是**速度与最优解的权衡**——安全气囊没时间规划，棋类游戏没兴趣快速瞎下
>
> 💡 **理解技巧**：混合式智能体是"实用主义的胜利"——LLM 智能体的 Agent Loop 本质上就是把大目标切成一串"边想边做"的微循环
>

>

## ✅ 知识点5: 任务环境定义——PEAS 模型

**设计智能体的第一步：先把它的任务环境描述清楚**

要理解智能体的运作，必须先理解它所处的任务环境。AI 领域通常使用 `PEAS 模型` 来精确描述任务环境。

- **PEAS 四维度**：
  - `P — 性能度量（Performance）`：什么叫"做得好"
  - `E — 环境（Environment）`：在什么世界里运行
  - `A — 执行器（Actuators）`：能做什么动作
  - `S — 传感器（Sensors）`：能感知到什么

**表 1.2 智能旅行助手的 PEAS 描述**（📋 原作此表以图片呈现，此处按正文描述整理）：

| 维度 | 智能旅行助手示例 |
|------|----------------|
| 性能度量 | 推荐与预订结果的合理性与用户满意度（示例整理，原作正文未逐一列出） |
| 环境 | 天气、航班票价与余票、景点信息等动态变化的数字世界 |
| 执行器 | 调用天气/搜索等 API、生成自然语言回复 |
| 传感器 | 用户输入、各 API 返回的数据流 |

**LLM 智能体数字环境的四个复杂特性**（直接影响智能体设计）：

- **部分可观察**：无法一次性获取全部信息——旅行助手查航班时只能看到 API 返回的部分数据 → 要求智能体具备**记忆**（记住已查询过的航线）和**探索**（尝试不同查询日期）的能力
- **随机性**（与确定性相对）：行动结果并非总是确定——两次相邻调用返回的机票价格和余票数量都可能不同 → 要求处理不确定性、监控变化并及时决策
- **`多智能体（Multi-agent）`**：环境中存在其他行动者——其他用户的预订行为、自动化脚本、航司动态调价系统都会直接改变环境状态（例如别人订走最后一张特价票）→ 对快速响应和策略选择提出更高要求
- **序贯且动态**："序贯"意味着当前动作会影响未来；"动态"意味着环境自身可能在智能体决策时发生变化 → "感知-思考-行动-观察"循环必须快速、灵活地适应持续变化的世界

> 💡 **理解技巧**：PEAS 回答"这个 Agent 活在什么世界、用什么手脚眼睛、怎样算成功"；环境四特性回答"这个世界有多难搞"——两者共同决定了 Agent 设计的复杂程度
>
> ⚠️ **关键警告**：别把"多智能体环境"窄化成"多个 AI 协作"——竞争对手的脚本、动态调价系统都是环境里的"其他智能体"

<a id="id6"></a>
## ✅ 知识点6: 智能体的运行机制——智能体循环

**智能体不是一次性完成任务，而是通过一个持续的循环与环境交互**

这个核心机制被称为 `智能体循环 (Agent Loop)`，它描述了智能体与环境之间的动态交互过程，构成其自主行为的基础（对应原作图 1.5）。

**循环的三个相互关联的阶段：**

1. **`感知 (Perception)`**：循环的起点。智能体通过传感器（API 监听端口、用户输入接口）接收环境输入。这些信息即 `观察 (Observation)`——既可以是用户的初始指令，也可以是上一步行动导致的环境状态变化反馈
2. **`思考 (Thought)`**：核心决策阶段。对 LLM 智能体而言是由大语言模型驱动的内部推理过程，可进一步细分为两个关键环节：
   - **`规划 (Planning)`**：基于当前观察和内部记忆，更新对任务和环境的理解，制定或调整行动计划——可能涉及将复杂目标分解为更具体的子任务
   - **`工具选择 (Tool Selection)`**：根据当前计划，从可用工具库中选择最适合执行下一步骤的工具，并确定调用参数
3. **`行动 (Action)`**：通过执行器执行具体行动——通常表现为调用一个选定的工具（代码解释器、搜索引擎 API），对环境施加影响

**闭环的形成**：行动并非终点。行动会引起 `环境 (Environment)` 的 `状态变化 (State Change)`，环境随即产生新的 `观察 (Observation)` 作为结果反馈；新观察在下一轮循环中被感知系统捕获，形成持续的"**感知-思考-行动-观察**"闭环。智能体正是通过不断重复这一循环，逐步推进任务，从初始状态向目标状态演进。

> 💡 **理解技巧**：注意"思考"被拆成了规划+工具选择两步——这正是知识点4中"混合式智能体"所说的审议过程；而行动+观察是反应过程。Agent Loop 就是混合式架构的工程实现
>
> 🔄 **知识关联**：这个循环在第四章会演化为经典的 `ReAct` 范式（`Reasoning + Acting`）——本章先建立"循环"直觉

## ✅ 知识点7: 智能体的感知与行动——交互协议

**Thought、Action、Observation：把 LLM 的语言推理和外部工具操作缝合起来的协议**

在工程实践中，要让 LLM 有效驱动智能体循环，需要一套明确的 `交互协议 (Interaction Protocol)` 来规范其与环境之间的信息交换。在许多现代智能体框架中，这一协议体现为对智能体**每一次输出的结构化定义**——输出不再是单一的自然语言回复，而是一段遵循特定格式、明确展示内部推理过程与最终决策的文本。

**输出的两个核心部分：**

- **`Thought（思考）`**：智能体内部决策的"快照"——以自然语言阐述它如何分析当前情境、回顾上一步观察、自我反思与问题分解、规划下一步具体行动
- **`Action（行动）`**：基于思考决定对环境施加的具体操作，通常以**函数调用**的形式表示

**示例**——规划旅行的智能体可能生成：

```text
Thought: 用户想知道北京的天气。我需要调用天气查询工具。
Action: get_weather("北京")
```

**协议的两端各有一个关键角色：**

- 外部 `解析器 (Parser)` 捕捉到 `Action` 字段，调用相应的 `get_weather` 函数
- 行动执行后环境返回结果（如包含详细天气数据的 JSON）。但原始机器可读数据通常含 LLM 无需关注的冗余信息，且格式不符合其自然语言处理习惯——因此**感知系统要扮演传感器的角色**：把原始输出处理、封装成简洁清晰的自然语言文本，即观察：

```text
Observation: 北京当前天气为晴，气温25摄氏度，微风。
```

这段 `Observation` 被反馈给智能体，作为下一轮循环的主要输入，供其进行新一轮的 `Thought` 和 `Action`。

**总结**：通过由 Thought、Action、Observation 构成的严谨循环，LLM 智能体得以将**内部的语言推理能力**与**外部环境的真实信息和工具操作能力**有效结合起来。

> ⚠️ **关键警告**：直接把工具返回的原始 JSON 塞回给 LLM 是常见反模式——冗余且不符合自然语言习惯；封装成简洁的 `Observation` 是协议的重要一环
>
> 📋 **术语提醒**：`Thought-Action-Observation` 三元组是全书反复出现的交互范式，简称 T-A-O 循环

## ✅ 知识点8: 动手实践（上）——准备工作与接入 LLM

**5 分钟实现第一个智能体：提示词模板是"说明书"，工具是"手脚"**

理论之后是最好的学习方式：亲手实践。本节从零构建一个智能旅行助手，处理的用户任务为：**"你好，请帮我查询一下今天北京的天气，然后根据天气推荐一个合适的旅游景点。"** 智能体必须先调用天气查询工具，把观察结果作为下一步依据，再调用景点推荐工具得出最终建议——完整走一遍刚学的理论循环。

**安装依赖：**

```bash
pip install requests tavily-python openai
```

- `requests`：最流行的 Python HTTP 库，用于访问网络 API
- `tavily-python`：AI 搜索 API 客户端，获取实时网络搜索结果（需在官网注册获取 API Key）
- `openai`：OpenAI 官方 Python SDK

**（1）指令模板——提示工程的核心**

驱动真实 LLM 的关键在于 `提示工程（Prompt Engineering）`。"指令模板"告诉 LLM 扮演什么角色、拥有哪些工具、如何格式化思考和行动——它是智能体的"说明书"，将作为 `system_prompt` 传递给 LLM。原作完整模板如下：

```python
AGENT_SYSTEM_PROMPT = """
你是一个智能旅行助手。你的任务是分析用户的请求，并使用可用工具一步步地解决问题。

# 可用工具:
- `get_weather(city: str)`: 查询指定城市的实时天气。
- `get_attraction(city: str, weather: str)`: 根据城市和天气搜索推荐的旅游景点。

# 输出格式要求:
你的每次回复必须严格遵循以下格式，包含一对Thought和Action：

Thought: [你的思考过程和下一步计划]
Action: [你要执行的具体行动]

Action的格式必须是以下之一：
1. 调用工具：function_name(arg_name="arg_value")
2. 结束任务：Finish[最终答案]

# 重要提示:
- 每次只输出一对Thought-Action
- Action必须在同一行，不要换行
- 当收集到足够信息可以回答用户问题时，必须使用 Action: Finish[最终答案] 格式结束

请开始吧！
"""
```

**（2）工具 1：查询真实天气** —— `get_weather(city: str) -> str`

- 使用免费天气服务 `wttr.in`，请求 JSON 格式数据：`https://wttr.in/{city}?format=j1`
- 从返回中提取 `current_condition` 的天气描述与摄氏温度，格式化成自然语言返回
- 用 `raise_for_status()` 与 `KeyError/IndexError` 捕获分别处理网络错误与数据解析错误

**（3）工具 2：搜索并推荐景点** —— `get_attraction(city: str, weather: str) -> str`

- 从环境变量读取 `TAVILY_API_KEY`，初始化 `TavilyClient`
- 构造精确查询：`'{city}' 在'{weather}'天气下最值得去的旅游景点推荐及理由`
- 调用 `tavily.search(..., include_answer=True)`——直接返回基于所有搜索结果的综合回答；没有综合回答时退化为格式化原始结果列表

**工具注册**——把所有工具函数放入字典，供主循环调用：

```python
available_tools = {
    "get_weather": get_weather,
    "get_attraction": get_attraction,
}
```

**（4）接入大语言模型** —— `OpenAICompatibleClient`

当前许多 LLM 服务（OpenAI、Azure、开源服务框架 Ollama、vLLM 等）都遵循与 OpenAI API 相似的接口规范，这种标准化带来极大便利。原作的通用客户端设计：

- `__init__(model, api_key, base_url)`：保存模型名，用 `OpenAI(api_key=..., base_url=...)` 初始化客户端
- `generate(prompt, system_prompt)`：组装 `system` + `user` 两条 messages，调用 `client.chat.completions.create(model=..., messages=..., stream=False)`，返回 `response.choices[0].message.content`，异常时打印并返回错误提示
- 实例化需提供三个信息：`API_KEY`、`BASE_URL`、`MODEL_ID`，具体值取决于服务商

> 💡 **理解技巧**：提示词模板完成了三件大事——定义角色、罗列工具签名、锁死输出格式（Thought/Action/Finish）。格式约束越死，后面的 Parser 越好写
>
> ⚠️ **关键警告**：工具函数返回的是**自然语言字符串**而非原始 JSON——这正是知识点7中"封装 Observation"要求的落地

<a id="id9"></a>
## ✅ 知识点9: 动手实践（下）——执行行动循环与运行案例

**一个 for 循环 + 三段正则 = 完整的 LLM 智能体**

主循环整合所有组件，通过格式化后的 Prompt 驱动 LLM 决策。原作完整代码：

```python
import re

# --- 1. 配置LLM客户端 ---
API_KEY = "YOUR_API_KEY"
BASE_URL = "YOUR_BASE_URL"
MODEL_ID = "YOUR_MODEL_ID"
TAVILY_API_KEY="YOUR_Tavily_KEY"
os.environ['TAVILY_API_KEY'] = "YOUR_TAVILY_API_KEY"

llm = OpenAICompatibleClient(
    model=MODEL_ID,
    api_key=API_KEY,
    base_url=BASE_URL
)

# --- 2. 初始化 ---
user_prompt = "你好，请帮我查询一下今天北京的天气，然后根据天气推荐一个合适的旅游景点。"
prompt_history = [f"用户请求: {user_prompt}"]

print(f"用户输入: {user_prompt}\n" + "="*40)

# --- 3. 运行主循环 ---
for i in range(5): # 设置最大循环次数
    print(f"--- 循环 {i+1} ---\n")

    # 3.1. 构建Prompt
    full_prompt = "\n".join(prompt_history)

    # 3.2. 调用LLM进行思考
    llm_output = llm.generate(full_prompt, system_prompt=AGENT_SYSTEM_PROMPT)
    # 模型可能会输出多余的Thought-Action，需要截断
    match = re.search(r'(Thought:.*?Action:.*?)(?=\n\s*(?:Thought:|Action:|Observation:)|\Z)', llm_output, re.DOTALL)
    if match:
        truncated = match.group(1).strip()
        if truncated != llm_output.strip():
            llm_output = truncated
            print("已截断多余的 Thought-Action 对")
    print(f"模型输出:\n{llm_output}\n")
    prompt_history.append(llm_output)

    # 3.3. 解析并执行行动
    action_match = re.search(r"Action: (.*)", llm_output, re.DOTALL)
    if not action_match:
        observation = "错误: 未能解析到 Action 字段。请确保你的回复严格遵循 'Thought: ... Action: ...' 的格式。"
        observation_str = f"Observation: {observation}"
        print(f"{observation_str}\n" + "="*40)
        prompt_history.append(observation_str)
        continue
    action_str = action_match.group(1).strip()

    if action_str.startswith("Finish"):
        final_answer = re.match(r"Finish\[(.*)\]", action_str).group(1)
        print(f"任务完成，最终答案: {final_answer}")
        break

    tool_name = re.search(r"(\w+)\(", action_str).group(1)
    args_str = re.search(r"\((.*)\)", action_str).group(1)
    kwargs = dict(re.findall(r'(\w+)="([^"]*)"', args_str))

    if tool_name in available_tools:
        observation = available_tools[tool_name](**kwargs)
    else:
        observation = f"错误:未定义的工具 '{tool_name}'"

    # 3.4. 记录观察结果
    observation_str = f"Observation: {observation}"
    print(f"{observation_str}\n" + "="*40)
    prompt_history.append(observation_str)
```

**主循环的四个关键设计：**

- `prompt_history` 累积全部历史（用户请求 + 每轮模型输出 + 每轮 Observation），每轮拼接后整体喂给 LLM——**智能体的"短期记忆"**
- 最多循环 5 次——防止无限循环的安全阀
- 正则截断：模型可能一次输出多对 Thought-Action，用前瞻断言只保留第一对
- `Finish[...]` 是约定的结束信号；否则解析工具名与参数（`(\w+)\(` + `(\w+)="([^"]*)"`），从 `available_tools` 查表调用

**运行案例分析（三轮成功执行）：**

| 轮次 | Thought 摘要 | Action | Observation |
|------|-------------|--------|-------------|
| 1 | 先获取北京今天天气，再据此推荐景点 | `get_weather(city="北京")` | 北京当前天气:Sunny，气温26摄氏度 |
| 2 | 已知晴朗温度适中，可推荐景点 | `get_attraction(city="北京", weather="Sunny")` | 颐和园（美丽湖景和古建筑）、长城（壮观景观和历史意义） |
| 3 | 已获得两个建议，可给出满意答复 | `Finish[今天北京的天气是晴朗的……推荐颐和园……或长城……]` | 任务完成，输出最终答案 |

这个案例集中演示了 `Thought-Action-Observation` 范式智能体的**四项基本能力**：**任务分解、工具调用、上下文理解和结果合成**。正是通过循环的不断迭代，智能体把模糊的用户意图转化为一系列具体、可执行的步骤并达成目标。

**总结**：通过以上步骤构建了一个完整的、由真实 LLM 驱动的智能体。其核心在于"**工具**"和"**提示工程**"的结合——这正是 LangChain、LlamaIndex 等主流智能体框架的设计精髓。

> 💡 **理解技巧**：整个智能体没有一行"智能"代码——所有智能都来自 LLM + 提示词，代码只负责三件事：维护记忆（prompt_history）、解析输出（正则）、执行工具（查表调用）
>
> ⚠️ **关键警告**：`range(5)` 的最大循环限制不是可有可无的——没有它，模型若始终不输出 `Finish` 就会无限调用 API，烧掉余额（原作习题 6 专门讨论了这一点）

**共同趋势**：AI 正在深度融入软件开发的全生命周期，通过构建高效的人机协同工作流，深刻重塑软件工程的效率边界与开发范式。

## ✅ 知识点11: 协作模式二——作为自主协作者的智能体

**从"命令-执行"到"目标-委托"：智能体成为主动的目标追求者**

第二种模式把自动化程度提升到全新层次：不再是手把手指导 AI 完成每一步，而是**将高层级目标委托给它**——智能体像真正的项目成员一样，独立地规划、推理、执行和反思，直到交付成果。它标志着我们与 AI 的关系从"命令-执行"演变为"目标-委托"。

从早期的 `BabyAGI`、`AutoGPT`，到如今更成熟的 `CrewAI`、`AutoGen`、`MetaGPT`、`LangGraph` 等框架，实现思路百花齐放，但架构范式大致可归纳为三个主流方向：

1. **单智能体自主循环**：早期典型范式，以 `AgentGPT` 为代表。核心是一个通用智能体通过"**思考-规划-执行-反思**"的闭环不断自我提示和迭代，完成开放式高层目标
2. **多智能体协作**：当前最主流的探索方向，模拟人类团队协作解决复杂问题，又可细分为三种模式：
   - **角色扮演式对话**：如 `CAMEL`——为两个智能体（如"程序员"和"产品经理"）设定明确角色和沟通协议，在结构化对话中协同完成任务
   - **组织化工作流**：如 `MetaGPT` 和 `CrewAI`——模拟分工明确的"虚拟团队"（软件公司/咨询小组），每个智能体有预设职责和工作流程（SOP），通过层级化或顺序化方式协作，产出完整代码库或研究报告等复杂成果
   - **灵活对话模式**：`AutoGen` 和 `AgentScope`——允许开发者自定义智能体间的复杂交互网络
3. **高级控制流架构**：以 `LangGraph` 为代表，侧重提供更强大的底层工程基础——把智能体执行过程建模为 `状态图（State Graph）`，更灵活可靠地实现**循环、分支、回溯以及人工介入**等复杂流程

这些架构范式共同推动自主智能体从理论构想走向更广泛的实际应用，教程后续章节还会进一步感受不同类型框架之间的差异和优势。

> ⚠️ **关键区分**：多智能体协作三模式别混淆——CAMEL 是"两个角色对话"，MetaGPT/CrewAI 是"一个公司上班"，AutoGen/AgentScope 是"自由组网"
>
> 🔄 **知识关联**：多智能体协作的理论先驱可追溯到明斯基的"心智社会"，见 [ch2-history-of-agents.md#id5](./ch2-history-of-agents.md#id5)

## ✅ 知识点12: Workflow 和 Agent 的差异

**Workflow 是让 AI 按部就班地执行指令，而 Agent 则是赋予 AI 自由度去自主达成目标**

两者都旨在实现任务自动化，但底层逻辑、核心特征和适用场景截然不同（对应原作图 1.6）。

**Workflow（工作流）——传统的自动化范式：**

- 核心：**对一系列任务或步骤进行预先定义的、结构化的编排**——本质是一个精确的、静态的流程图，规定在何种条件下、以何种顺序执行哪些操作
- 典型案例（费用报销审批流程）：员工提交报销单（触发）→ 金额小于 500 元，直接由部门经理审批 → 金额大于 500 元，先部门经理审批、再流转至财务总监审批 → 审批通过后通知财务部打款。每一步、每个判断条件都被精确预设

**Agent——具备自主性的、以目标为导向的系统：**

- 不仅执行预设指令，还能在一定程度上理解环境、进行推理、制定计划，并动态采取行动以达成最终目标——LLM 扮演"大脑"角色
- 以 1.3 节的旅行助手为例，收到"查北京天气并推荐景点"指令后的处理过程充分展现自主性：
  1. **规划与工具调用**：把任务拆解为 ① 查询天气 ② 基于天气推荐景点，自主选择并调用天气查询 API，把"北京"作为参数传入
  2. **推理与决策**：假设 API 返回"晴朗，微风"，LLM 大脑推理"晴天适合户外活动"，据此在知识库或搜索引擎中筛选北京的户外景点（故宫、颐和园、天坛公园等）
  3. **生成结果**：综合信息给出完整、人性化的回答
- **关键**：整个过程中没有任何写死的 `if 天气=晴天 then 推荐颐和园` 规则——如果天气是"雨天"，Agent 会自主推理并推荐国家博物馆、首都博物馆等室内场所

**这种基于实时信息进行动态推理和决策的能力，正是 Agent 的核心价值所在。**

> ⚠️ **关键区分**：判断一个系统是 Workflow 还是 Agent，就看决策逻辑是**预先写死的**还是**运行时推理出来的**——和用了多少 AI 技术无关
>
> 💡 **理解技巧**：Workflow 的价值也不容否定——报销审批这种规则明确的场景，静态流程图比 LLM 推理更便宜、更可靠、更可审计

## ✅ 知识点13: 本章小结——四个核心问题

**一张关于智能体的基础认知框架**

本章从最基本的问题出发，回答了四个核心问题：

1. **什么是大语言模型驱动的智能体？** 不再仅仅是执行预设程序的脚本，而是能够**自主推理和使用工具的决策者**
2. **智能体如何工作？** 以智能体循环为基础——这个持续的闭环是智能体处理信息、做出决策、影响环境并根据反馈调整自身行为的基础
3. **如何构建智能体？** 本章的实践核心——以"智能旅行助手"为例，亲手构建了完整的、由真实 LLM 驱动的智能体
4. **智能体有哪些主流的应用范式？** 两种主流交互模式：以 GitHub Copilot、Cursor 等为代表的"开发者工具"（增强人类工作流），以及以 CrewAI、MetaGPT、AgentScope 等为代表的"自主协作者"（独立完成高层级目标）；并厘清了 Workflow 与 Agent 的差异

**下一章预告**：智能体是如何从最初的构想一步步演进至今的？第二章将探索智能体的发展历史，见 [ch2-history-of-agents.md](./ch2-history-of-agents.md)。

## 🔑 核心要点总结

1. **智能体 = 传感器 + 执行器 + 环境 + 自主性**——四要素中真正赋予"智能"的是自主性：基于感知和内部状态独立决策，形成感知-行动闭环
2. **传统智能体五型演进**：`反射智能体` → `基于模型的反射智能体` → `基于目标的智能体` → `基于效用的智能体` → `学习型智能体`——每代新类型都在回答上一代解决不了的问题
3. **LLM 新范式的本质**：预训练获得隐式世界模型与涌现能力，使智能体能处理模糊的自然语言指令，展现规划与推理、工具使用、动态修正三大新能力
4. **三个分类维度**：决策架构（AIMA 四型+学习元能力）、时间与反应性（反应式/规划式/混合式）、知识表示（符号/亚符号/神经符号）——LLM 智能体是神经符号主义的实践
5. **Agent Loop + T-A-O 协议**：感知-思考（规划+工具选择）-行动-观察循环是运行机制；`Thought-Action-Observation` 交互协议把 LLM 的语言推理与外部工具操作缝合起来
6. **手写智能体的全部秘密**：提示词模板（角色+工具+输出格式）+ 两个工具函数 + 一个 for 循环——智能全在 LLM，代码只管记忆、解析、调用
7. **协作两模式与根本区分**：开发者工具（增强人）vs 自主协作者（目标委托）；Workflow 按部就班 vs Agent 自主达成——动态推理是 Agent 的核心价值

## 📌 考试速记版

- **定义四要素**：`传感器(Sensors)`、`执行器(Actuators)`、`环境(Environment)`、`自主性(Autonomy)`
- **五型演进（原作名称）**：`反射智能体(Simple Reflex Agent)` → `基于模型的反射智能体(Model-Based Reflex Agent)` → `基于目标的智能体(Goal-Based Agent)` → `基于效用的智能体(Utility-Based Agent)` → `学习型智能体(Learning Agent)`
- **五型各自回答**：该做什么 → 世界什么样 → 如何达成目标 → 怎样最满意 → 如何自我改进
- **LLM 三大新能力**：规划与推理、工具使用、动态修正
- **反应式 vs 规划式**：速度/低开销 vs 远见/高成本；混合式 = "思考-行动-观察"微循环
- **知识表示三派**：符号主义（透明但脆弱）、亚符号主义（鲁棒但黑箱）、神经符号主义（系统1+系统2）
- **PEAS**：`Performance / Environment / Actuators / Sensors`
- **环境四特性**：部分可观察、随机性、多智能体、序贯且动态
- **Agent Loop 三阶段**：感知 → 思考（规划+工具选择）→ 行动 →（状态变化）→ 新观察
- **T-A-O 协议**：`Thought`（决策快照）→ `Action`（函数调用）→ Parser 执行 → `Observation`（自然语言封装）
- **实践四件套**：`AGENT_SYSTEM_PROMPT`、`get_weather`/`get_attraction`、`available_tools` 字典、5 轮主循环
- **四项基本能力**：任务分解、工具调用、上下文理解、结果合成
- **自主协作三范式**：单智能体循环（AgentGPT）、多智能体协作（CAMEL/MetaGPT/AutoGen）、状态图控制流（LangGraph）
- **金句**：Workflow 按部就班执行指令；Agent 自主达成目标——**动态推理是核心价值**

**记忆口诀**：传感执行加自主，闭环构成智能体；反射模型到学习，五型演进问题驱；LLM 带来新范式，规划工具动态修；三维分类看架构，时间反应知识表；PEAS 先把环境定，循环感知思考行；T-A-O 协议缝合紧，提示工具手写灵；工具增强人，协作接目标，Workflow 死板 Agent 活。
