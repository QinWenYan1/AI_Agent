## ✅ 知识点1: 什么是智能体 (Agent)

**一个能通过感知环境、自主决策并采取行动来达成目标的系统**

智能体不是新概念——它在 AI 领域已经存在了几十年。但大语言模型的出现，彻底改变了构建智能体的方式。理解 Agent 的本质定义，是区分"AI 工具"和"AI 智能体"的第一步。

- **智能体 (Agent)** 的定义：通过`传感器(Sensors)`感知环境，借助`执行器(Actuators)`自主行动以达成目标的实体
- 核心循环：**感知(Perception) → 思考(Thought) → 行动(Action) → 观察(Observation) → 循环**

> 💡 **理解技巧**：Agent 和普通程序的区别在于"自主性"——普通程序按固定流程执行，Agent 根据感知到的信息**动态决定**下一步做什么

<a id="id2"></a>
## ✅ 知识点2: PEAS 模型——描述任务环境

**设计 Agent 的第一步：搞清楚它在什么环境里工作**

- `PEAS` 是描述 Agent 任务环境的四维模型：

  | 维度 | 全称 | 含义 | 旅行助手示例 |
  |------|------|------|-------------|
  | `P` | Performance | 性能度量——什么叫"做得好" | 推荐准确率、用户满意度 |
  | `E` | Environment | 环境——在什么世界里运行 | 天气 API、景点数据库 |
  | `A` | Actuators | 执行器——能做什么动作 | 调用 API、生成文本 |
  | `S` | Sensors | 传感器——能感知到什么 | 用户输入、API 返回结果 |

> 📋 **术语提醒**：`PEAS` = Performance, Environment, Actuators, Sensors——设计任何 Agent 前都应该先用 PEAS 梳理清楚任务边界

<a id="id3"></a>
## ✅ 知识点3: 传统智能体的五种类型

**在大语言模型出现之前，智能体是如何被分类的？**

- 五种经典智能体类型，按智能程度从低到高排列：

  | 类型 | 英文名 | 核心机制 | 类比 |
  |------|--------|---------|------|
  | 简单反射型 | `Simple Reflex Agent` | 条件→动作规则，无记忆 | 膝跳反射 |
  | 基于模型型 | `Model-Based Agent` | 维护内部状态，追踪环境变化 | 有经验的老司机 |
  | 基于目标型 | `Goal-Based Agent` | 有明确目标，搜索达成路径 | 导航系统 |
  | 基于效用型 | `Utility-Based Agent` | 在多个目标间权衡取舍 | 投资经理 |
  | 学习型 | `Learning Agent` | 从经验中自我改进 | AlphaGo |

> 🔄 **知识关联**：LLM Agent 本质上是把"基于目标"和"学习型"的能力，通过大语言模型的推理能力统一了起来——详见 [第二章 ch2-history-of-agents.md#id6](./ch2-history-of-agents.md#id6)

<a id="id4"></a>
## ✅ 知识点4: LLM 驱动的新范式

**大语言模型如何改变 Agent 的构建方式？**

- 传统 Agent 需要人工编写规则、设计状态机——**智能上限取决于开发者编码的知识量**
- LLM 驱动的 Agent 利用大语言模型的**通用推理能力**作为"大脑"：
  - **规划能力**：能将复杂目标分解为子步骤
  - **工具调用**：能决定何时调用外部 API/工具
  - **动态修正**：遇到错误能自主调整策略重试
- LLM Agent 不需要为每个场景手写规则——模型通过`上下文学习(In-context Learning)`和`思维链(Chain-of-Thought)`自行推理

> ⚠️ **关键区分**：传统 Agent 的智能上限 = 开发者编码的规则数量；LLM Agent 的智能上限 = 模型的推理能力 + 可用的工具

<a id="id5"></a>
## ✅ 知识点5: Agent 与 Workflow 的本质区别

**智能体和自动化流程的根本差异在哪？**

这是理解 Agent 最关键的区分。很多人把"自动化工作流"误认为是"智能体"，但两者有本质不同。

- **Workflow（工作流）**：**按部就班地执行指令**——每一步都是预定义好的，遇到意外情况就停住或报错
- **Agent（智能体）**：**赋予 AI 自由度去自主达成目标**——你给目标，它自己决定怎么做，遇到问题会自己调整策略

  | 维度 | Workflow | Agent |
  |------|:--:|:--:|
  | 决策方式 | 预定义规则 | 动态推理 |
  | 灵活性 | 低——路径固定 | 高——路径自主 |
  | 错误处理 | 报错或跳过 | 自主修正重试 |
  | 适用场景 | 结构化、确定性任务 | 非结构化、探索性任务 |
  | 例子 | CI/CD Pipeline | Claude Code 修 Bug |

> ⚠️ **关键区分**：不是说 Workflow 不好——对于确定性高的任务，Workflow 更可靠、成本更低。Agent 的价值在于处理**不确定性**

<a id="id6"></a>
## ✅ 知识点6: 实践：智能旅行助手

**动手构建第一个 Agent**

第一章的实践项目是构建一个"智能旅行助手"——用户输入目的地，Agent 查询天气并推荐景点。

- 这个看似简单的应用包含了 Agent 的完整循环：
  1. **感知**：接收用户输入的目的地
  2. **思考**：LLM 推理——需要查天气、需要推荐景点
  3. **行动**：调用天气 API
  4. **观察**：获取天气结果
  5. **再思考**：根据天气推荐合适的景点
  6. **输出**：生成最终推荐

- 通过这个项目，读者能直观理解 Agent 不是"一问一答"，而是一个**多轮交互的循环过程**

> 💡 **理解技巧**：旅行助手虽然简单，但它包含了 Agent 的所有核心要素——感知、规划、工具调用、观察反馈。复杂 Agent 只是这个循环的更多轮次和更复杂的工具集

## 🔑 核心要点总结

1. **Agent 的核心是自主性**——感知 → 思考 → 行动 → 观察的循环，关键在于"动态决策"
2. **PEAS 模型是设计 Agent 的第一步**——先搞清楚性能度量、环境、执行器、传感器
3. **五种传统类型**从简单反射到学习型，智能程度递增——LLM Agent 融合了"基于目标"和"学习型"的能力
4. **Agent ≠ Workflow**——Workflow 按部就班，Agent 自主达成目标，价值在于处理不确定性
5. **LLM 改变了 Agent 的构建方式**——从手写规则到利用模型的通用推理能力

## 📌 考试速记版

- **Agent 四组件**：感知、规划、行动、记忆
- **PEAS**：Performance, Environment, Actuators, Sensors
- **Agent vs Workflow**：Workflow = 预定义路径；Agent = 自主达成目标
- **五种类型**：反射 → 模型 → 目标 → 效用 → 学习
- **LLM Agent 优势**：规划、工具调用、动态修正

**记忆口诀**：感知思考行动观察，Agent 循环不停转；PEAS 四维多考量，目标效用学习强。
